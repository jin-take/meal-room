# MealRoom MVP 要件定義

この文書は2026年8月15日時点の実装済み仕様を示します。

## 目的

家族・カップルが同じRoomで料理、献立、買い物リストを共有し、「献立を決める」から「必要な食材を整理する」までを一続きにすることを目的とします。

## 対象ユーザー

- Roomを最初に作成するホスト
- 招待コードを受け取って参加するメンバー

`host`と`member`は現状、画面表示とデータ上の区別にのみ使用します。どちらも料理、献立、買い物リストを編集でき、ホスト専用操作の認可は実装していません。

## 機能要件

### Room

- Room名と利用者名を入力してRoomを作成できる。
- Room作成時に6文字の英数字招待コードを自動生成する。
- 招待コードと利用者名を入力して既存Roomへ参加できる。
- 招待コードを表示し、クリップボードへコピーできる。
- Roomに所属するホストとメンバーを一覧表示できる。
- 現在の端末から退出し、ローカルセッションを削除できる。

招待コードの再発行、メンバー削除、Room削除、ホスト移譲は対象外です。

### 料理

- 料理名、カテゴリ、食材、メモ、任意のレシピURLを登録できる。
- 登録済み料理を一覧表示、編集、削除できる。
- 食材は「、」、`,`、改行で入力し、空白を正規化して文字列配列として保存する。
- 食材の数量、単位、価格、在庫は保持しない。
- 料理を削除した場合、その料理を参照する献立も削除する。

### 献立

- 月曜日始まりの1週間を表示する。
- 前週、次週へ移動し、「今週」で現在週へ戻れる。
- 日付ごとに朝食、昼食、夕食の料理を選択できる。
- 料理を「未定」に戻せる。

### 買い物リスト

- 1つの月カレンダー上で開始日と終了日を順番に選択できる。
- 選択中の開始日、終了日、期間内の日付をテーマ色で識別できる。
- 終了日から選び始めた場合でも、2つの日付を時系列に並べて範囲を確定する。
- 選択期間は開始日と終了日を含めて最大31日とする。
- 選択期間の献立に含まれる料理から、食材名を重複排除して自動項目を作成する。
- 再集計時は同名項目の購入済み状態と、手動追加した項目を可能な範囲で維持する。
- 項目を手動追加、削除、購入済み／未購入へ切り替えできる。

### 保存と共有

- `VITE_CLOUDFRONT_BASE_URL`が設定されている場合、Room単位のJSONをCloudFront経由でS3へ保存する。
- 招待コードの検索用に`rooms/index.json`を使用する。
- 環境変数が設定されていない場合、ブラウザのローカルストレージへ保存する。
- 端末ごとのRoomセッションと端末IDをローカルストレージへ保存する。
- Roomは3秒ごと、および画面へ戻った際に再取得する。
- 料理、献立、買い物の変更は端末内に保持し、画面上部の同期ボタンを押した時だけRoom JSONをPUTする。
- 未同期変更がある状態で取得した他端末の変更は、ID単位の差分統合によって画面へ反映する。

## UI要件

- 表示言語は日本語とする。
- スマートフォンを優先したレスポンシブレイアウトとする。
- テーマ色は`#7CB342`とする。
- Untitled UIを参考に、明確な文字階層、8px基準の余白、ニュートラルカラーで構成する。
- カードの枠線は使わず、背景色、余白、最小限の影で情報をグルーピングする。
- 320px以上の画面幅で、ヘッダー、フォーム、カレンダー、操作ボタンが横にはみ出さないようにする。
- ロゴとアプリアイコンには透過画像`asset/icon-meal-room-transparent.png`を使用する。
- 下部ナビゲーションからホーム、料理、献立、買い物、Roomへ移動できる。

## 非機能要件と現状

- S3バケットは非公開とし、CloudFront Origin Access Controlでアクセスする。
- S3ではバージョニングとAES256暗号化を有効にする。
- `rooms/*`はCloudFrontでキャッシュしない。
- Room JSONの目安は1MB以下とするが、クライアントまたはS3で上限検査は行っていない。
- WebアプリはCloudFrontの`/index.html`を明示的に読み込める。
- Flutterは通信断を検知して日本語のオフライン表示を出し、復帰時に再読み込みする。

## セキュリティと競合に関する制約

- 招待コード、メンバーID、端末IDだけでは本人認証を行わない。
- `version`は同期ごとに増加するが、S3直接PUTでは保存前の比較を行わない。同期の直前に最新データと差分統合するものの、完全に同時のPUTは最終書き込み優先となる。
- `rooms/index.json`の更新も排他制御を行わない。
- 現在のCloudFront URLとRoom IDを知るクライアントに対して、細かなRoom単位の認可は行わない。
- 公開運用へ移行する際は、認証、Room単位認可、サーバー側入力検証、監査ログ、競合制御を追加する。
