# rebuild-child 作業指示

作成日: 2026-11-08

## 目的

再構築の次の意思決定に使う「選択肢と影響の比較資料」を準備してください。いまは本番AWSの読み取り権限待ちなので、AWSリソースの変更や本番データへのアクセスなしで進められる範囲に限定します。

## 着手前に読む資料

1. [再構築ステータス](rebuild-status.md) — 進捗・決定・リスクの正本
2. [再構築計画](rebuild-plan.md)
3. [要件定義](requirements.md)
4. [OpenAPI](openapi.yaml)
5. [現行インフラ棚卸し](current-infrastructure.md)
6. [現行データ棚卸し](data-inventory.md)

## 担当作業

`docs/rebuild-project/decision-options.md`を作成し、次の未決事項について、選択肢・長所と短所・実装や運用への影響・決定に必要な情報を整理してください。

1. Roomの権限とライフサイクル（招待、メンバー削除、host移譲、退室、Room削除）
2. 既存端末のmember IDとGoogleログイン後のMealRoom User UUIDを結び付ける方法
3. 同期の競合制御とリアルタイム通知方式
4. MySQLの運用方式と可用性の選択肢
5. Room単位の切替条件、観測期間、切り戻し条件
6. 広告要件（出稿かサイト内掲載か）。主要再構築後まで保留する場合の理由も記録

## 成果物の形式

各項目を次の形式で記載してください。

- 現在の合意・制約
- 選択肢（最低2案。選択肢が実質1案なら、その理由）
- 影響（利用者体験、セキュリティ、運用負荷、費用、移行への影響）
- 判断に必要な前提や追加調査
- PMまたはユーザーに確認したい質問
- 推奨案があれば、前提と理由を添えて提案（最終決定はしない）
- 関連するADRや要件文書の更新候補

実トラフィックと本番費用が未確認なので、根拠のない数値見積もりは出さず、必要な入力値と見積もり手順を示してください。AWSやGoogleのサービス仕様を根拠にする場合は公式資料を参照してください。

## 作業上の制約

- 本番AWS、S3、DNS、CloudFront、IAM、データを変更しない。
- 認証情報、利用者名、Room ID、招待コード、Room JSON原本を成果物に書かない。
- 要件を勝手に確定したり、現在の合意済み要件を覆したりしない。
- 実装コードやIaCの変更は行わない。この依頼は意思決定材料の作成です。
- 既存文書と食い違いを見つけたら、黙って一方を書き換えず、差分と確認事項を報告する。

## 完了時

1. 成果物を`docs/rebuild-project/decision-options.md`に保存する。
2. [再構築ステータス](rebuild-status.md)の担当表・実行履歴を更新し、完了した範囲と未解決事項を記録する。
3. 変更ファイル、根拠、ユーザーに決めてもらう項目を簡潔に報告する。

## 完了条件

- 6項目すべてを確認し、根拠と未確認事項を区別している。
- 費用や性能について、未調査の数値を事実のように書いていない。
- 既存要件との矛盾やユーザー判断が必要な点が一覧になっている。
- ステータス正本が更新され、PMが次の判断に使える。
